# MEZGEB — SIGNATURE SMS EXPERIENCE

Build a premium, concise, privacy-first transactional SMS system for Mezgeb (መዝገብ). Deliver all messages in English, Amharic and Afaan Oromo with English fallback. Use the verified sender identity; never invent a short code, provider, delivery confirmation or account event.

## Authentication
Phone signup/verification, sign-in OTP, phone change, MFA challenge and reauthentication only where supported by the live Auth configuration. Generate and verify OTPs exclusively through Supabase, not client-side code. The native Supabase SMS template is shared across flows; use a neutral message or a verified Send SMS Hook for localized rendering. Never expose OTPs in logs, previews, analytics or push. Do not hardcode expiry or length. Resends, throttling, CAPTCHA and abuse controls must use verified project settings. Normalize phone numbers to E.164, validate country and provider routing, prevent account enumeration, handle invalid/expired codes and duplicate submissions gracefully. Keep email/password login working. Do not activate phone auth until account linking, verified identity and recovery tests pass. SMS is not phishing-resistant; prefer supported stronger factors for sensitive financial actions.

## Security and business notifications
Implement every catalog event using authoritative server-side committed events only. Account confirmation, reset requested, password/email/phone changes, identity linked/unlinked, MFA added/removed, new sign-in. Send only to verified recipients and use neutral copy. Phone changes must not send sensitive information to an unverified new number. For business reminders, backup reminders, sync attention and app updates use opt-in preferences, deduplication, quiet hours where appropriate, and an unsubscribe/preference mechanism. Do not send financial balances, Dube debt, tax IDs or customer names. Never text customers without separately verified consent and authorization. App update messages only after the compatible signed release is published. No SMS on every sale/expense by default.

## Delivery architecture
Verify the existing Mezgeb project, supported provider and Ethiopian network coverage (Ethio telecom/Safaricom Ethiopia), registered sender, current costs and applicable rules. Configure a server-side provider or signed Supabase Send SMS Hook, verify signatures/replay and validate destinations. Secrets server-only. Use durable outbox with unique event ID, idempotency, bounded retry/backoff, authenticated delivery receipts and redacted logs. Avoid retrying ambiguous provider responses without idempotency. Rate-limit per user, phone and IP; enforce daily spend cap, fraud detection and emergency kill switch. GSM-7 vs Unicode segment budget: measure actual encoded messages, preserve Unicode meaning, never truncate OTP. Separate essential security SMS from opt-in reminders; no promotions.

## Android experience and release
Design premium phone field with country code, accessible OTP input with paste/autofill where supported (no broad SMS-reading permission), resend countdown based on server rules, clear offline/error states, masked destination and verified success. Do not change app signing key/package or clear data. SMS is optional; keep existing email flow. Test real authorized test numbers across supported networks, invalid/expired/reused OTP, rate limiting, duplicated callbacks, localized segments, offline recovery, identity linking and replay. No live sends, provider activation, schema changes or auth policy changes until review and verified access. Report source-ready, test-ready and live separately.
