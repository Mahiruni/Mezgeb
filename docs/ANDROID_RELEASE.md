# Mezgeb 1.0.1 — safe production signing and ledger transfer

Version code 8, same package and web origin. The 1.0.0 non-debuggable candidate passed package checks but has no permanent signing credentials. 1.0.1 adds Android Storage Access Framework export through an AndroidX WebKit origin-restricted main-frame message bridge. JSON backups are flushed before export and confirmed only after the native document write closes. Existing ledger replacements require an explicit backup when records are present; cloud conflict exports await completion. Native bridge does not read files or use a public storage permission.

Owner setup: run `bash scripts/configure-android-signing.sh --existing /private/path/mezgeb.p12 mezgeb` on a trusted computer with gh, keytool and openssl. Only use `--new` for a new signing identity after protecting existing records; the script refuses to overwrite a key and checks the certificate before sending credentials directly to GitHub Actions secrets. Do not paste the key or password into chat or commit it. Keep a separate encrypted offline copy. The workflow produces a signed APK only on a manual dispatch of the reviewed main branch, when all secrets and the pinned SHA-256 are configured. Pull requests always build unsigned release candidates; unreviewed PR code never receives signing credentials. No native update manifest is enabled until actual compatibility and distribution are verified.

For a signing mismatch, keep the existing app installed; use Settings → Data & backup, verify the saved JSON and counts and cloud recovery (if enabled). Do not uninstall or reset until restore is validated. Existing old debug APKs may have nonmatching keys and may not support the new native file bridge. A new signing identity cannot overwrite them. Real-device export/import, email verification, localization and authentic presenter recordings remain release gates.

## 1.0.4 stability gate
Android 15 and Android 16 emulator upgrade tests use a synthetic ledger seeded on the exact 1.0.3 revision, install 1.0.4 over it using the same CI debug certificate, and assert unchanged financial values, receipt number, customer credit and repayment, local storage origin and actual rendered UI while offline and after restart. This does not prove compatibility with an independently signed installed APK. A manual production signing dispatch now requires the runtime gate and fails rather than reporting success when signing credentials are missing. Bundled Android updates no longer promise to refresh into a new interface; native update preparation flushes records and exposes a user-initiated package check. No real customer data or production account is used.

### Offline validation correction
